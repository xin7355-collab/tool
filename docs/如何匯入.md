# 搬家後的設定清單

原本住在 `8rknrz2dbw-ai/transcript-tool`（帳號被停權，讀不到了），
2026-08-10 從離線備份包還原到 **`xin7355-collab/tool`**。

程式碼裡的 `OWNER` / `REPO` 已經改成新帳號，但下面這幾樣**存在 GitHub 上、不在程式碼裡**，
所以沒辦法跟著搬，要重新設一次。

## 1. Secrets（產線要用）

repo → **Settings → Secrets and variables → Actions → New repository secret**

| 名稱 | 用途 | 必要性 |
|---|---|---|
| `GROQ_API_KEY` | 沒字幕的影片改用語音辨識，在 [console.groq.com/keys](https://console.groq.com/keys) 免費申請 | 建議加 |
| `YT_COOKIES` | **想要全自動就要設**——沒有的話 GitHub 機房 IP 會被 YouTube 擋掉，只能用手機補抓。取得方式見 [如何取得cookies.md](如何取得cookies.md) | 建議加 |
| `GDRIVE_KEY` | **想接 Google 雲端硬碟才要**——服務帳號的 JSON 金鑰，貼整份。做法見 [如何接Google雲端硬碟.md](如何接Google雲端硬碟.md) | 選用 |
| `YT_PROXY` | **多半不需要**——免費代理是機房 IP，跟現在一樣會被擋；有用的住宅代理要付費，而你手機本來就是住宅 IP。理由見[同一份文件](如何取得cookies.md) | 不建議 |

> 「📡 追蹤」那組排程（`watch.yml`）只用 GitHub 內建的 `GITHUB_TOKEN`，不用另外加 secret。

### Variables（跟 Secrets 同一頁，但是隔壁那個分頁）

同一頁上面有 **Secrets** 和 **Variables** 兩個分頁。Variables 也不會跟著搬家，
而且它沒設的時候不會報錯，只會安靜地退回預設值——所以最容易被漏掉。

| 名稱 | 建議值 | 沒設會怎樣 |
|---|---|---|
| `ASR_BACKEND` | `groq` | 退回機房 CPU 跑本機 Whisper。一小時的節目要跑好幾小時，整批撞到 120 分鐘逾時，`GROQ_API_KEY` 明明設好了卻完全沒用到 |
| `GROQ_LLM_MODEL` | **不要設** | 設了反而會出事——舊值 `llama-3.1-8b-instant` 已於 2026-08-16 被 Groq 停用，留著會蓋掉程式裡的新型號，摘要與 AI 校對整批 404。要換模型直接改工作流那一行 |

> 2026-08-23 就是踩到這個：音檔全部卡在 inbox 轉不出來，Actions 卻一片綠。
> 現在程式改成「有 `GROQ_API_KEY` 就自動走 Groq」，這個 Variable 不設也會對，
> 而且真的退回本機 Whisper 時日誌會印警告、整批失敗會變紅燈。

## 2. GitHub Pages

repo → **Settings → Pages → Source** 選 **`gh-pages`** 分支。
網址會是 `https://xin7355-collab.github.io/tool/`。

> `pages.yml` 是「附加」模式，只覆蓋 `index.html` / `manifest.webmanifest` / `sw.js` / `assets/`，
> 不會動到 `gh-pages` 上的 `transcripts/`，所以逐字稿不會被洗掉。

## 3. 網站上的 Token

打開網站 → **⚙ 設定** → 重新填 GitHub Token。
[建立新 Token](https://github.com/settings/personal-access-tokens/new)：
Repository access 選 **Only：tool**，Permissions 的 **Contents** 和 **Issues** 都給 **Read and write**。

舊帳號那把 Token 已經失效，不用留。

## 4. 手機上的 yt2deck.py（有在用才需要）

腳本的自動更新是去抓舊帳號的網址，現在那邊 404，它會安靜地照舊版跑、
然後上傳到已經不存在的 repo。**要手動重裝一次**，在 a-Shell 執行：

```
python3 -c "import urllib.request as u;open('yt2deck.py','wb').write(u.urlopen('https://raw.githubusercontent.com/xin7355-collab/tool/main/scripts/yt2deck.py').read())"
```

順便把 `deck_token.txt` 換成上面第 3 步的新 Token：

```
python3 yt2deck.py --set-token
```

> **沒換會怎樣**：影片照樣下載得下來（那步不用 Token），但一上傳就
> `Token 認證失敗（401 Bad credentials）`。舊帳號那把是 `ghp_` 開頭的
> classic token，長度 40 看起來很正常，所以很容易誤以為是別的問題——
> 其實是帳號停權後跟著失效了。新的是 `github_pat_` 開頭。
>
> 現在腳本開跑前會先驗一次 Token，不會等到抓完幾十 MB 才報錯。
